# 设备底册完整度分析（虚构数据演示）

三个不同来源各交一份**虚构**巡检名单；应用按「设备编号 + 经确认的别名」归并设备，
用三份名单的重合情况（捕获-再捕获 / 对数线性模型）估计**可能一份都没出现的设备量**。

**本应用不接任何真实资产系统；所有名单、设备、别名、人员均为编造。**

## 运行

```bash
# 任选其一启动静态服务（ES 模块需要 http 协议，不能直接双击打开）
python3 -m http.server 8000
# 或
npx serve .

# 然后访问 http://localhost:8000
```

## 测试与数据再生成

```bash
node tests/run-tests.mjs     # 核心逻辑测试（21 个）
node tests/smoke-dom.mjs     # UI 冒烟测试（最小 DOM 垫片，10 个）
node tools/generate-data.mjs # 以固定种子重新生成虚构数据（含统计自检）
```

## 功能地图

| 区块 | 内容 |
|---|---|
| 1 · 名单整理 | 外观规范化（全半角/大小写/空白）、剔除无效记录、名单内去重；不做语义合并 |
| 2 · 身份决议 | 已确认别名自动应用；疑似同名**不自动合并**，待定别名逐项「合并 / 分开」，即时生效 |
| 3 · 重合表 | 2×2×2 捕获历史表 + 韦恩图；点击格子查看具体设备及来源记录；000 格不可观测 |
| 4 · 总体估计 | 已确认并集（实际看见）与漏登估计（依赖假设）分开呈现；9 个模型对比；不可估/不可辨识明示 |
| 5 · 待定别名影响 | 逐个待定映射的合并/分开影响、全组合影响范围、前后对照（同一模型） |
| 6 · 方法说明 | 流程、可辨识性、不可估规则、反例解释 |

## 方法要点

- **模型族**：从「三名单相互独立」到「全部两两相关」，交互项显式声明；
  可指定某两份名单相关（如 A·B）。对 7 个观测格做 Poisson 对数线性拟合（IRLS），外推 n₀₀₀。
- **不可辨识**：含三因子交互的饱和模型需 8 个参数，但只有 7 个观测格——
  未观测组合不能从数据中直接验证。
- **不可估**：重合为零、数据过稀（重复捕获 < 3）、参数无有限解（空格致 MLE 发散）时报告不可估；
  拟合只接受非负整数计数。
- **已确认并集 ≠ 漏登估计**：前者是实际看见的数量，后者是依赖假设的外推，两者始终分开。
  不能选拟合最好的一版就宣称底册已完整——G² 只衡量对观测格的拟合。
- **反例**：「北山水厂」中名单 A、B 共用同一承包商，对偏远设备有共同盲区（强正相关），
  独立模型明显低估漏登量；含 A·B 交互项的模型更接近虚构真值。

```
js/core/overlap.js      重合表

tests/                  核心测试 + UI 冒烟测试
```
